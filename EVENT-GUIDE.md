# Event guide

Public site: `http://<server>:3000`

Organizer page: `http://<server>:3000/admin`

Admin manual: `http://<server>:3000/admin/manual`

## During the event

1. Keep **Whitelist validation** enabled when only listed emails can submit and vote.
2. Disable **Whitelist validation** when any valid email can submit and vote. The saved list remains available.
3. Add participant email addresses to the **Email whitelist** when you use validation.
4. Use the single-email controls for small changes.
5. Use **Bulk edit** to replace the complete whitelist. Separate emails with spaces, commas, or new lines.
6. Leave **Submissions** open while participants build their projects.
7. Review each entry. Select **Accept** or **Reject**.
8. Select **Remove** only when you must delete a submission, its votes, and its screenshot.
9. Confirm that accepted entries appear in the gallery.
10. Select **Open voting** when the showcase starts. This action closes submissions.
11. Ask attendees to vote with a valid email address.
12. Select **Total-vote-only view** to show one large vote total. Select **Admin scoreboard** to open the detailed project scores on a separate page.
13. If an attendee votes again, ask the attendee to confirm the vote change.
14. Select **Close voting**.
15. Select **Publish results**. The public **Results** tab then shows the final ranking and vote bars.

Use **Reset all votes** only when you must restart voting. This action permanently removes every recorded vote.

Each email can submit one project. A repeated email shows a warning and keeps all form content. Ask the participant to contact event staff if the first submission was a mistake or the participant must submit again.

The service stores uploaded screenshots in the local Docker volume. Gallery cards open the public project URL that each participant submitted.
